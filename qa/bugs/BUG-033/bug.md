# BUG-033 · An image drawn more than once on a page is extracted only once: the second use (another item or figure) has no picture

**Suspected module:** src/pipeline/pipeline.py::_extract_embedded_images (uses only rects[0] of each image object)

## Description

A PDF can draw the same image object (same xref) more than once on a page, for example the same part drawing for two items of a parts list. The pipeline keeps only the first place where it is drawn, so the second item or figure has no picture of its own. No unique drawing is lost, but a RAG consumer cannot see the picture next to the second item.

Seen in LOGIQ_S8 v1.13 (agent drafts): p832 items 17 and 18 (sec_0127, power cord drawing, xref 5820); p563 the second board of a figure (sec_0086); p802 items 21 and 22 (sec_0122).

## Root cause

Confirmed in code: `_extract_embedded_images` in src/pipeline/pipeline.py reads `page.get_image_rects(xref)` and uses only `rects[0]`. Each image object is extracted once per page.

## What was done

- 2026-10-07: found by the QA lead in the Phase 0 review of LOGIQ_S8 v1.13 (BUG-011 work); registered by request of the reviewer (Oscar Munoz).

## Fix

Proposed (deterministic, no AI): extract one image for each distinct place where the object is drawn on the page (skip a rect that is the same as or inside an earlier one). Check that repeated small icons on one page do not become noise: simulate on the 7 manuals and look at every added image, as in Phase 0.
