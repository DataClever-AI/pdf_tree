# BUG-031 · Printed text is deformed in the tree: line-break hyphens kept, leader dots, split subscripts, spaced degree signs, control characters, a lost or repeated sign; the text and its place are kept

**Suspected module:** Docling text and table cells (PyPdfium/docling-parse); no normalization step yet (planned Phase 4)

## Description

The text is in the tree and in the right place, but it is written differently from the PDF. Exact search for the word fails, so a RAG consumer can miss it.

- Line-break hyphens kept with a space: 'pres- sure' (AUTOMATIC p27), 'emis- sion' (2002 p94), 'auto- matically' (SOMATOM p149). About 130 cases, almost all in table cells; Docling joins them in paragraphs.
- Leader dots in Contents tables: 'Overview . . . . . 1-1', and the page cell starts with '. ' (LOGIQ_S8, 2002).
- Split subscripts: 'CO 2', 'SpO 2' instead of 'CO2', 'SpO2' (Philips p83, DOC p200). About 400 cases.
- Spaced degree signs: '45 ° C' instead of '45°C' (Philips p110, LOGIQ_S8 p82). About 150 cases.
- Control characters: 'com\x02 pressor' (2002 p158), 'V\x02 Nav' (LOGIQ_S8 p687). About 210 cases, mostly in text nodes.
- A lost or repeated sign: a plus-minus sign read as '+', a legend letter written twice ('a a module name'), repeated characters ('1 mVp Vpp ,206 bpm' instead of '1 mVpp, 206 bpm', Philips p443).

## Root cause

Not confirmed. The text readers keep the PDF's line-break hyphen, leader dots and subscript or degree glyphs as separate runs, and there is no clean-up step. Docling joins paragraph lines but not lines inside table cells. The control character is probably a soft hyphen glyph without a Unicode mapping.

## What was done

- 2026-10-07: created from the TRIAGE rows of the final re-measurement, by request of the reviewer (Oscar Munoz). Proposal: ../doc/propuestas/PROPUESTA_REGLAS_TRIAGE_2026-10-07.md.
- 2026-10-08: the reviewer decided that a line-break hyphen kept in a table cell is FAIL Low in every manual. The new rule in `root_causes.json` matches the rows with that note (`Low by the reviewer rule of 2026-10-08 (line-break hyphens in cells)`).
- 2026-10-08: BUG-036 ("deformed text"), created the same day, was merged into this bug by request of the reviewer, so that one bug holds every kind of deformed text. The scope grew from table cells to all text (subscripts, degree signs, control characters).

## Fix

Planned in Phase 4 (deterministic, no AI): a text normalization step for table cells and text nodes.

- Join 'pres- sure' when the joined word is printed on the page.
- Remove runs of leader dots.
- Join a subscript digit with its letters.
- Remove the spaces around '°' before C/F.
- Drop control characters and keep the plus-minus glyph.

Each rule needs a check that it does not damage real text, such as '2-4 brake' or 'pre- and post-'. Test with the LOGIQ_S8 Contents tables, the Philips tables on p457–458 and the cases above.
