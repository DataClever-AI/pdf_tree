# BUG-026 · QA run.log captured from a shared Streamlit console mixes the run of another manual

**Suspected module:** QA process (log capture), not pipeline code

## Description

Where it was seen: `qa/Philips-MP20-MP90-Manual/v1/logs/run.log`. Lines 1-14 are the Philips abort; from line 15 it contains another run (`fitz: 138 bookmarks, 916 pages`, i.e. LOGIQ_S8). QA evidence for that version is unreliable.

## Root cause

The log was copied from the console of a Streamlit session that went on to process another manual.

## What was done

- 2026-09-28: detected while diagnosing BUG-025.
- 2026-09-29: registered in the root-cause catalogue `qa/confidence_index/root_causes.json`.

## Fix

The v2 run stores the log captured by the run itself. v1 is kept unchanged (QA versions are never overwritten).
