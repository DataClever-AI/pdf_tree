# BUG-025 · An orphan destination-less cover bookmark appended at the end of the outline aborts the whole pipeline

**Suspected module:** src/tree_builder/bookmark_sanity.py (out_of_order hard failure)

## Description

Where it was seen: `Philips-MP20-MP90-Manual` (496 pages, 868 bookmarks). `bookmark_sanity: 2 hard failures — aborting`. The last two bookmarks are `M8000-9001K_cover_22sep08.pdf` (no destination) and its child `IntelliVue Patient Monitor` pointing to page 1 (the cover). The earlier diagnosis 'two merged documents' in `qa/README.md` was wrong.

## Root cause

The cover was inserted after the outline was generated; the editor appended a destination-less bookmark named after the cover file, which breaks the order check.

## What was done

- 2026-09-04: blocker recorded in `qa/README.md` with an incorrect diagnosis.
- 2026-09-28: diagnosis corrected in `qa/README.md`; fixed; v2 run added (commit `0ba00df`).
- 2026-09-29: registered in the root-cause catalogue `qa/confidence_index/root_causes.json`.

## Fix

Same `repair_bookmarks()`: a destination-less bookmark whose subtree only points before the first content bookmark is treated as orphan front matter and dropped. A destination-less container whose children point into the body is kept (tested).

## Verification

Unit tests for both shapes. Full v2 run: cover subtree dropped (2 bookmarks), 865 sections, Structure and Precision PASS, Coverage FAIL (2 orphan blocks, left to review), `verify_version.py` PASS.
